Chapter 5 · about 30 minutes

A shell

The part people actually use: a prompt where you type commands and your OS answers. You have all the pieces; now you put them together.

The idea

A shell is a loop: show a prompt → read a line → split it into a command and its arguments → find the command → run it. A table of {name, help text, function} makes adding commands easy: one line each.

Turning the computer off or restarting it is hardware too: QEMU turns off when you write 0x2000 to port 0x604, and every PC restarts when you send 0xFE to the keyboard controller on port 0x64.

Do it

  1. The shell

    Chapter 5. Write src/shell.c and shell.h with shell_run(): show a coloured prompt with the OS name, read a line with input_getc (support Backspace, ignore other control keys, max 127 characters, echo what is typed), split the command from its arguments, and look it up in a table of commands {name, help text, function}.

    Commands: help (lists all commands with their help text, aligned), clear, echo <text>, about (OS name, version, uptime), uptime (hh:mm:ss), color <name> (changes the text colour), reboot (keyboard controller, 0xFE on port 0x64), shutdown (outw(0x604, 0x2000) for QEMU, then halt) and crash (runs ud2 to show the panic screen). Unknown commands print a short message.

    Put the OS name and version in src/os.h. kernel_main calls shell_run() after setting everything up.

    make run

    Type help, then try every command.

  2. Invent your own commands

    Pick one or two, and ask your AI for them one at a time:

    • calc 12 * 7: a calculator for whole numbers.
    • Command history with the up arrow.
    • guess: guess-the-number, using the timer ticks as randomness.
    • banner hello: big letters.
    • time: the real date and time from the PC's clock chip (the CMOS RTC, ports 0x70/0x71).

It works when

  • help lists your commands and each one works.
  • shutdown closes QEMU; crash shows the panic screen.
  • You added at least one command of your own.
