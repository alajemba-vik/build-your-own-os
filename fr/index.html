C’est quoi, un système d’exploitation ?

C’est le programme qui démarre en premier et qui gouverne l’ordinateur : il parle au matériel (écran, clavier, mémoire, minuteur), il décide de ce qui s’exécute et quand, et il offre aux autres programmes une façon simple d’utiliser tout cela. Windows, macOS, Linux, Android et iOS sont des systèmes d’exploitation (OS). En leur cœur se trouve le noyau (kernel), et c’est lui que nous construisons.

Quand vous appuyez sur le bouton d’alimentation, voici ce qui se passe. Vous écrirez les parties en gras :

Mise sous tension→Micrologiciel (BIOS)→Chargeur d’amorçage→boot.S→kernel_main()→pilotes→votre shell

Va-t-il remplacer Windows ou macOS ?

Non. Votre OS tourne dans QEMU, un programme gratuit qui se fait passer pour un PC entier (un émulateur). Rien ne change sur votre ordinateur, et si votre OS plante, il suffit de fermer la fenêtre. C’est pourtant un vrai OS : le même code pourrait démarrer un vrai PC.

Nous visons le PC Intel 32 bits classique (x86), parce que c’est le mieux documenté et le plus simple pour commencer. Il fonctionne de la même façon sur les Mac Intel, les Mac Apple Silicon (M1–M4) et les PC Windows.

Comment vibe-coder un OS

Vous décrivez ce que vous voulez, l’IA écrit le code, et vous l’exécutez, le lisez et la guidez. Un OS s’y prête très bien : l’IA connaît les astuces du matériel, et vous apprenez à quoi sert chacune. Cinq règles pour que cela marche :

  1. Donnez le brief à votre IA. Le kit de départ contient AGENTS.md : les règles du projet (32 bits, pas de bibliothèque C, clang, QEMU…). Les agents de code le lisent tout seuls ; avec une IA de chat, collez-le en premier. Il est en anglais, mais votre IA vous répondra en français si vous lui écrivez en français.
  2. Un chapitre, une étape à la fois. Chaque chapitre vous donne un prompt. Ne demandez pas tout l’OS d’un coup : vous obtiendriez quelque chose que vous ne sauriez pas réparer.
  3. Demandez pourquoi, pas seulement quoi. Chaque chapitre propose des questions à poser. Si vous ne savez pas expliquer une ligne, demandez jusqu’à ce que vous sachiez.
  4. Lancez-le après chaque modification avec make run. Quand ça casse, collez l’erreur complète à l’IA.
  5. Enregistrez avec Git quand quelque chose marche. Bloqué ? Chaque chapitre contient le code de référence d’un OS terminé, pour comparer.

Quelle IA ?

Agents de code

Claude Code, Codex, Cursor, GitHub Copilot, Gemini CLI. Ils lisent les fichiers de votre dossier et AGENTS.md, modifient le code et peuvent lancer make. Le choix le plus simple.

IA de chat

ChatGPT, Claude.ai, Gemini. Collez AGENTS.md au début, puis les fichiers à modifier, et recopiez les réponses dans vos fichiers.

Sans IA ?

Ça marche aussi. Chaque chapitre explique l’idée, et le code de référence est entièrement commenté (en anglais). Lisez-le, puis écrivez-le vous-même.
