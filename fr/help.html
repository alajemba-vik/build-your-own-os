Demandez à votre IA de la bonne façon

Je suis au chapitre [N] du tutoriel « Construisez votre OS » (x86 32 bits, multiboot, clang + ld.lld, QEMU, pas de bibliothèque C : voir AGENTS.md). J’ai modifié : [QUELS FICHIERS, QUOI]. J’ai lancé : [LA COMMANDE]. Je m’attendais à : [CE QUI DEVRAIT SE PASSER]. À la place, je vois : [CE QUI SE PASSE, AVEC L’ERREUR COMPLÈTE OU LES DERNIÈRES LIGNES AFFICHÉES]. Explique d’abord ce que veut dire l’erreur, puis donne-moi la plus petite correction possible.

L’erreur complète compte : collez tout, à partir de la première ligne en rouge. Pour les plantages, collez l’écran de panique ou la sortie de la commande -d int,cpu_reset ci-dessous.

Problèmes fréquents

Vous voyezCe que cela veut dire et que faire
clang: command not found ou ld.lld: No such fileLes outils ne sont pas installés ou pas trouvés. Mac : brew install llvm lld. Windows : lancez dans Ubuntu la ligne sudo apt install … de l’installation. Vérifiez que vous êtes bien dans la fenêtre Ubuntu, pas dans PowerShell.
Des erreurs sur i686-elf ou ld.lld sur MacC’est probablement le clang d’Apple qui est utilisé. Lancez brew install llvm lld ; le Makefile trouvera alors tout seul la version de Homebrew.
make: *** No targets specified ou No rule to make targetVous n’êtes pas dans le dossier de votre OS. Lancez cd ~/my-os.
undefined symbol: memset / memcpyLe compilateur s’en sert pour les grosses copies. Écrivez-les dans src/string.c (chapitre 2).
undefined symbol: __udivdi3 / __umoddi3Une division ou un % sur 64 bits. Utilisez un décalage, ou des nombres 32 bits.
fatal error: 'stdio.h' file not foundIl n’y a pas de bibliothèque C dans un noyau. Utilisez votre propre kprintf. Seuls stdint.h, stddef.h, stdbool.h et stdarg.h existent.
QEMU affiche Error loading uncompressed kernel without PVH ELF NoteQEMU n’a pas trouvé l’en-tête multiboot. Vérifiez que .multiboot vient en premier dans linker.ld, que le nombre magique est juste et que vous avez compilé pour i686 (32 bits).
QEMU s’ouvre et se ferme aussitôtUne triple faute (un plantage pendant le traitement d’un plantage). Voir plus bas.
Taper ne fait rienCliquez d’abord dans la fenêtre QEMU. Puis vérifiez sti, que l’IRQ 1 est démasquée, et l’End Of Interrupt (chapitre 4).
Les lettres ne sont pas à leur placeVotre clavier est en AZERTY et la table est en QWERTY. C’est normal ; voir le défi du chapitre 4.
Pas de fenêtre QEMU sous WindowsWindows 10 ne sait pas afficher les fenêtres des applications Linux. Utilisez make run-text. Sous Windows 11, lancez wsl --update dans PowerShell, puis wsl --shutdown, et rouvrez Ubuntu.
Coincé dans make run-textAppuyez sur Échap puis 2, tapez quit, Entrée. Ou fermez le terminal.
La souris est bloquée dans la fenêtre QEMUAppuyez sur Ctrl Alt G (Mac : Ctrl ⌥ G).
Ça marchait avant et maintenant c’est casségit diff montre ce qui a changé depuis votre dernier enregistrement. git restore . y revient (et jette les modifications).

Voir pourquoi QEMU a planté

qemu-system-i386 -kernel build/kernel.elf -no-reboot -d int,cpu_reset 2>&1 | tail -40

Les dernières lignes montrent les interruptions juste avant le redémarrage. v=0d est une faute de protection générale, v=0e un défaut de page, v=08 une double faute. Collez-les à votre IA avec les fichiers que vous avez modifiés.

Trouver la ligne qui a planté

Prenez l’eip de l’écran de panique et demandez aux outils dans quelle fonction il se trouve :

"$(brew --prefix llvm)/bin/llvm-addr2line" -f -e build/kernel.elf 0x00101234
addr2line -f -e build/kernel.elf 0x00101234     # s’il manque : sudo apt install binutils

Glossaire

Noyau (kernel)Le cœur d’un OS : le code qui contrôle le matériel et fait tourner tout le reste.
Chargeur d’amorçageLe petit programme (bootloader) qui charge le noyau en mémoire et le démarre. Le nôtre est intégré à QEMU.
MultibootUne façon standard pour un chargeur de trouver et démarrer un noyau : un nombre magique et quelques options.
QEMUUn programme qui se fait passer pour un PC entier, pour que votre OS tourne dans une fenêtre.
FreestandingDu code C sans système d’exploitation ni bibliothèque C en dessous.
Script de l’éditeur de liensIndique à l’éditeur de liens (linker) où chaque partie du programme va en mémoire.
Pile (stack)La mémoire où le C garde les variables locales et les adresses de retour. Elle grandit vers le bas.
Mode texte VGAL’écran vu comme 80 × 25 caractères en mémoire, à 0xB8000.
Port d’E/SUn numéro pour parler à un périphérique avec inb/outb, distinct des adresses mémoire.
Port sérieCOM1 : envoie du texte octet par octet. QEMU le relie à votre terminal.
InterruptionUn signal qui fait s’arrêter le processeur pour exécuter un gestionnaire, puis continuer.
ExceptionUne interruption levée par le processeur parce que le code a fait une erreur (0–31).
IRQUne demande d’interruption venant d’un périphérique : 0 est le minuteur, 1 le clavier.
GDTGlobal Descriptor Table : les segments de mémoire. Nous en définissons deux qui couvrent tout.
IDTInterrupt Descriptor Table : quel gestionnaire s’exécute pour chaque interruption.
PICLa puce qui rassemble les IRQ du matériel et les transmet au processeur.
PITLa puce minuteur qui bat au rythme que nous choisissons.
ScancodeLe numéro qu’envoie un clavier pour la position d’une touche.
PageUn bloc de 4 Kio de mémoire, l’unité que l’OS distribue.
Allocateur par bitmapGarde un bit par page pour savoir lesquelles sont libres.
Tas / kmallocD’où viennent les petits morceaux de mémoire quand le noyau en demande.
Triple fauteUn plantage pendant le traitement d’un plantage pendant le traitement d’un plantage. Le processeur redémarre.
Vibe codingConstruire en décrivant ce que l’on veut à une IA, en exécutant le résultat et en la guidant.
