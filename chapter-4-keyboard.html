Timer and keyboard

Your first two drivers. The timer lets your OS count time; the keyboard lets you type. After this chapter, your OS reacts to you.

The idea

  • Hardware raises IRQs (interrupt requests). The PIC chip collects them and passes them to the CPU as interrupts 32–47 (we moved them there in chapter 3). After each one, we must send the PIC an End Of Interrupt, or it never sends another.
  • The PIT timer counts at 1,193,182 Hz. Divide that by 100 and it raises IRQ 0 a hundred times a second. Each one is a tick.
  • The keyboard raises IRQ 1 for each key pressed or released. We read a scancode from port 0x60: a number for the key's position, not a letter. We turn it into a letter with a table, and track Shift ourselves.
  • Keys wait in a small ring buffer (a queue that wraps around) until someone reads them.
  • sti turns interrupts on. hlt sleeps until the next interrupt: no wasted CPU while waiting for a key.

Do it

  1. The timer

    Chapter 4, part 1. Add irq_install(irq, handler) in idt.c: it stores the handler and unmasks that IRQ in the PIC. In isr_handler, for interrupts 32-47 call the handler and send End Of Interrupt (to both PICs for IRQ 8-15). Ignore spurious IRQ 7 and 15.

    Then src/timer.c and timer.h: program the PIT channel 0 to 100 Hz, count ticks on IRQ 0, and add timer_ticks(), uptime_seconds() and timer_sleep_ms(). Turn interrupts on with sti at the end of kernel_main, then print the uptime once a second as a test.

    make run

  2. The keyboard

    Chapter 4, part 2. Add src/keyboard.c and keyboard.h: on IRQ 1 read the scancode from port 0x60, ignore key releases (except to track Shift), translate scancode set 1 to characters with two tables for a US QWERTY layout (normal and shifted), handle Caps Lock, and turn the arrow keys (0xE0 prefix) into special codes KEY_UP, KEY_DOWN, KEY_LEFT, KEY_RIGHT. Put keys in a 64-byte ring buffer.

    Add input_poll() that returns the next key or -1, and input_getc() that waits for a key with hlt. Both should also accept characters typed in the serial terminal (\r means Enter, 0x7F means Backspace). Replace the uptime test with a loop that prints every key I type.

    make run

    Click inside the QEMU window, then type.

  3. Understand it

    Ask your AI: What happens if I forget the End Of Interrupt? Why is the variable that counts ticks volatile? Why do the arrow keys send two bytes?

On an AZERTY keyboard, letters come out in QWERTY places (A gives Q). That's expected: scancodes are key positions. A nice challenge: ask your AI to add a French AZERTY table and a way to switch.

It works when

  • The boot shows [ OK ] Timer and [ OK ] Keyboard.
  • What you type appears, with capitals when you hold Shift.
  • Your terminal shows the same text, and typing in the terminal works too.

Nothing happens when I type: did you call sti? Is IRQ 1 unmasked? Do you send End Of Interrupt after every IRQ, including the timer's? If the timer works only once, it's the End Of Interrupt.
