Memory

Programs need memory, and the OS is the one that hands it out. You find out how much RAM the PC has, which parts are free, and you write an allocator that gives out pieces of it.

The idea

  • Not all addresses are RAM you can use: the first megabyte holds the BIOS and the screen, some areas belong to hardware, and your kernel itself sits at 1 MiB. The bootloader gives us a memory map: a list of areas, each marked usable (type 1) or not. boot.S already passes it to kernel_main.
  • We cut memory into pages of 4 KiB and keep a bitmap: one bit per page, 1 = used, 0 = free. 128 MiB is 32,768 pages, so the whole bitmap fits in 4 KiB.
  • linker.ld defines kernel_end, the first address after our kernel, so we never hand out our own code.
  • For small objects we add a heap with kmalloc. The simplest one just gives the next free bytes and never takes them back. Real ones do better; that can be your challenge.
  • Careful: dividing 64-bit numbers on a 32-bit CPU needs a helper library we don't have. Use shifts (>> 12 is "divide by 4096").

Do it

  1. The page allocator

    Chapter 6. kernel_main receives the multiboot magic and a pointer to the multiboot info. Write src/memory.c and memory.h: define struct multiboot_info and the memory map entry struct (packed). In memory_init: mark every page used, then free the pages of every area of type 1 in the memory map (flag bit 6; fall back to mem_upper if there is no map), then mark the first 1 MiB and the kernel (up to the kernel_end symbol from linker.ld) as used again. Use a bitmap with one bit per 4 KiB page, for up to 512 MiB. Don't use 64-bit division.

    Add page_alloc() (returns the address of a free page, or 0), page_free(), pages_total() and pages_used(). Add a bump kmalloc from a 64 KiB static heap, 16-byte aligned. Print "[ OK ] Memory: N MiB found" at boot, and add shell commands mem (totals) and alloc (takes one page and prints its address).

    make run

    Run mem, then alloc a few times.

  2. Play with it

    In the Makefile, change -m 128M to -m 256M and run again: mem should follow. Ask your AI to add a memmap command that lists every area of the memory map with its type.

  3. Understand it

    Ask your AI: What is in the first megabyte? Why are pages 4 KiB? What would paging add (the next big step in a real OS)?

It works when

  • The boot shows about 127 MiB found with -m 128M.
  • alloc gives a new address each time, above where your kernel ends.

"undefined symbol: __udivdi3" (or __umoddi3): a 64-bit division slipped in. Replace it with a shift, or convert to 32-bit first.
