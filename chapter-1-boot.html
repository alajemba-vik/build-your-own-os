Chapter 1 · about 20 minutes

Boot and say hello

Your starter already boots. In this chapter you find out exactly how, line by line, with your AI, and you make the first screen your own.

The idea

A PC starts its firmware (the BIOS), which loads a bootloader. Our bootloader is built into QEMU: qemu-system-i386 -kernel build/kernel.elf. It follows a standard called Multiboot: it looks for a magic number, 0x1BADB002, at the start of our file, loads the kernel at 1 MiB in memory and jumps into it, with the CPU already in 32-bit mode.

From there, it's all ours:

  • src/boot.S (assembly) holds the magic number, sets up a stack (memory C needs for its variables) and calls kernel_main.
  • linker.ld says where each piece of the kernel goes in memory.
  • src/kernel.c writes to the screen. In text mode the screen is memory: 80 × 25 cells starting at address 0xB8000, 2 bytes each (the character, then its colour). Write there, and letters appear.
  • Makefile builds it with --target=i686-elf -ffreestanding: code for a bare 32-bit PC, with no operating system and no C library under it. We are the operating system.

Do it

  1. Run it

    make run

    You see the hello message. Close QEMU.

  2. Let your AI explain it

    Read AGENTS.md and every file in this project. Explain in simple words what happens from the moment QEMU starts until "Hello" appears on the screen. Go file by file: Makefile, linker.ld, src/boot.S, src/kernel.c. For boot.S, explain each line.

    Then ask about anything you don't get. Good questions:

    • Why does the stack start at the top and grow down?
    • What would happen if kernel_main returned?
    • What is in the colour byte 0x0B?
    • Why can't I use printf here?

  3. Make it yours

    Change the first screen: show my name instead of "my own operating system", draw a border around the whole screen with the box-drawing characters of the VGA font (code page 437), and use at least three colours. Explain how the colour byte works (text colour, background colour). Keep everything in kernel.c.

    make run

  4. Break it on purpose

    In boot.S, change 0x1BADB002 to another number and run make run. QEMU refuses to start it: no magic number, no boot. Put it back.

It works when

  • QEMU shows your name, a border and several colours.
  • You can say what boot.S, linker.ld and 0xB8000 are for.
