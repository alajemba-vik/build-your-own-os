Chapter 2 · about 30 minutes

A real console

Writing letters at fixed places gets old fast. You build a console like a terminal's: a cursor, new lines, scrolling, colours, and your own printf. And a second output, the serial port, that shows up in your terminal and makes debugging much easier.

The idea

  • The console remembers a row and column. Each character goes there and moves the cursor on. \n goes to the next row.
  • When the last row is full, you scroll: copy every row one up and clear the bottom one.
  • The blinking cursor is moved by talking to the VGA chip through I/O ports 0x3D4 and 0x3D5. Ports are a second address space for hardware, used with the outb and inb instructions.
  • kprintf is our printf (the k is for kernel). It uses stdarg.h, which the compiler gives us even without a C library.
  • The serial port (COM1, port 0x3F8) sends bytes one by one. make run connects it to your terminal, so every line your OS prints also appears there, and you can copy it into your AI.

Do it

  1. Build the console

    Chapter 2. Create src/io.h with outb/inb/outw helpers (inline assembly). Then src/console.c and src/console.h: a text console on the VGA screen with a cursor position, newline, backspace, tab, scrolling when the screen is full, colours (an enum of the 16 VGA colours) and moving the blinking hardware cursor.

    Add src/serial.c for COM1 (0x3F8) so every character printed on the console is also sent to the serial port (send \r before \n).

    Add src/printf.c with kprintf supporting %s %c %d %u %x %p %%, a width like %5d, zero padding like %02u, and left alignment like %-10s. Also a ksnprintf that writes into a buffer. And src/string.c with memset, memcpy, memmove, strlen, strcmp, strncmp, because we have no C library.

    Update kernel_main to clear the screen, print a coloured title, a few lines with numbers (negative, hex), then 30 numbered lines to test scrolling.

    make run

  2. Understand it

    Ask your AI:

    • How does va_list work when there is no C library?
    • Why do we write volatile for the screen memory?
    • Why might the compiler call memset even if I never wrote it?

  3. Make it yours

    Print a coloured ASCII-art logo with your OS's name when it starts. Ask your AI to make one (keep it under 7 lines and 60 columns), and to escape the backslashes.

It works when

  • The 30 lines scroll and the last ones are visible.
  • kprintf("%d %x %05u", -42, 255, 7) prints -42 ff 00007.
  • The same text appears in your terminal (the serial port).

"undefined symbol: memset" (or memcpy): the compiler uses them for big copies, and we have no C library. Make sure string.c exists and is built.

Strange symbols instead of letters: each screen cell is character | (colour << 8). Check the character is cast to uint8_t first.
